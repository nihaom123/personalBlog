# 产品/项目画像

- **项目**: 温水煮冷水博客运营
- **类型**: content
- **生成时间**: 2026-10-23 19:15 +0800
- **文档作用**: 明确项目服务对象、使用场景和价值。

## 目标用户或受众

- **主力读者**：18–30 岁、常刷 B 站/微博/知乎热榜的网民；对二次元、数码折腾、日常吐槽感兴趣；习惯碎片化阅读，停留时间短，愿意在轻松话题下接梗留言。
- **次要读者**：通过搜索「XX 是什么梗」「XX 怎么设置」进来的效率型读者，需要明确、不啰嗦的答案。
- **博主（阿胜）**：站点所有者，只做审核与最终拍板，不参与日常生产。

## 核心场景

1. **通勤/午休刷一下**：打开首页，看到 1–3 条新文章卡片，标题有趣就点进去，读完顺手留一句。
2. **热搜延伸阅读**：在微博/B站看到某个话题后搜索，落到本站文章，读完发现「这站还有点意思」，去看其他栏目。
3. **技术问题落地**：搜「Astro 部署 Cloudflare 报错」类问题，进入「技术折腾」文章，按步骤解决，可能留言补充。
4. **站内闲逛**：从留言板 → 关于 → 二次元页面，形成多页浏览。

## 痛点、需求或流程

- 读者痛点：热搜内容多为搬运和营销号，缺少有趣、有个人态度、不吵不闹的观点。
- 读者需求：轻松、有梗、能共鸣、不用动脑但有信息量；有地方说话。
- 博主痛点：想有个人站点但不希望每天写稿、怕内容枯竭、怕踩红线。
- 博主需求：低人力、可审核、可随时改节奏、数据可看。

## 参考对象与替代方案

- 参考站点：各类「每日梗图/日报」类个人站、B站 UP 主图文动态、少数派式个人博客。
- 替代方案：只发 B站动态（受平台审核与算法影响）、只在朋友圈发（无沉淀）、不发（站点长期空置）。
- 本站差异化：**自有域名 + 可检索的自有内容 + 可评论的长期沉淀**，而不是一次性动态。

## 成功标准

一周试运行（V1）结束时，达成以下任两条即为成功：

1. 7 天累计发布 70 篇，无一篇触碰红线；
2. 站内评论累计 ≥ 20 条（含博主回复），且至少 5 条来自陌生读者；
3. 单篇最高阅读（或 Web Analytics 访问量）≥ 50；
4. 有 ≥ 3 篇被外部平台（B站/微博/X/群聊）自然分享；
5. 博主每周实际投入 ≤ 1 小时（仅审核与拍板）。

## 用户旅程或执行旅程

**读者旅程**：热搜/搜索/分享进入 → 首页或文章页 → 读完一篇 → 侧栏/文末推荐下篇 → 留言板或评论区互动 → 订阅 RSS 或加友链 → 回访。

**运营旅程（每周）**：
周一 → 抓取上周热搜与本周候选话题；周中 → 批量写 70 篇草稿（`draft: true`）→ 提交 PR/直接提交 → 博主抽检 10% → 通过后进入发布池；每日 → 定时任务按 3/4/3 批次将当天稿件置为已发布并触发构建；周日 → 复盘数据、调整下周选题与节奏。

## 定位

**「一个每天有梗、能留言的个人小站」**——不做资讯站、不做垂直媒体，做有活人感的私人内容集合。内容比例：生活打底，技术与二次元穿插，热点负责带来流量。

## 约束条件

- 单人运营，无团队、无预算、无模型 API Key（首周手动写稿）。
- 站点为静态构建（Astro → Cloudflare Workers），每次发布都会触发一次完整构建，注意构建时长与频率成本。
- 技术栈固定为 Firefly + Astro + pnpm，非必要不引入新框架。
- 无 ICP 备案（境外托管）；内容需自我约束，避免高风险话题。
- 发布时间集中在早（07:30）、中（12:30）、晚（20:30）三批。
